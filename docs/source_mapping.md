## 4. Git 仓库数据的缺陷与本项目必须解决的问题

虽然 Git 仓库中包含了完整数据，但它**完全不适合直接供 AI 或大模型系统高效使用**，存在以下核心问题：

| 问题项 | Git 仓库现状 | 本知识库规范目标 |
| :--- | :--- | :--- |
| **存储格式** | JavaScript CommonJS 变量定义 (`var GUA_INTERPRETATION = ...`) | 语言中立的标准 JSON / JSONL / Markdown |
| **网页噪声** | 包含爬虫残留文本（如 `未经允许不得转载：易学界 » ...`） | 彻底过滤所有爬虫噪音、版权水印、乱码符号 |
| **张铭仁解卦字段混杂** | 把 17 个维度杂糅在一整个纯文本字符串中 | 结构化拆分为独立的键值对或细分子属性 |
| **AI/LLM 读取代价** | 453KB 单一巨大文件，Token 消耗巨大，AI 容易注意力漂移 | 拆分为单卦独立微文件（~7KB/卦）及细粒度分块（Chunking） |
| **检索友好度 (RAG)** | 无元数据标签、无向量检索 Chunk 切分、无问答对 | 建立携带 `[卦名] [爻位] [断事类别] [学派]` 等标签的高密度分块 |
| **象数规则数据化** | 象数理分散在代码逻辑函数中，非数据字典 | 抽离为开箱即用的 JSON 规则库（AI 可直接做 Prompt 上下文推理） |
